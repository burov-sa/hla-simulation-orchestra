# HLA Simulation Orchestra (Kafka-based)

Данный проект представляет собой распределенную систему оркестрации симуляций (HLA - High Level Architecture), основанную на Apache Kafka и Protocol Buffers. Система позволяет объединять несколько независимых симуляционных моделей (например, созданных в AnyLogic) в единый ансамбль для совместного моделирования с жесткой синхронизацией модельного времени.

## 🏗 Архитектура системы

Система состоит из двух основных компонентов:

1.  **KafkaOrchestrator (Оркестратор):** Центральный узел, который управляет жизненным циклом симуляции. Он отслеживает регистрацию моделей, синхронизирует шаги времени (барьер), маршрутизирует агентов между моделями и обрабатывает сбои (через Heartbeat и Dead Letter Queue).
2.  **KafkaOrchestrant (Оркестрант):** Обертка над конкретной моделью. Она подключается к Kafka, регистрируется в оркестраторе, отправляет Heartbeat и выполняет команды (начать шаг, завершить симуляцию). Оркестрант абстрагирован от конкретного движка через интерфейс `IEngine`.

### Основные сервисы Оркестранта:
*   `RegistrationOrchestrantService`: Отправляет сообщения `ONLINE`/`OFFLINE`.
*   `HeartbeatOrchestrantService`: Периодически сообщает оркестратору, что модель жива.
*   `ConsumerOrchestrantService`: Читает команды от оркестратора и принимает агентов.

### Протокол обмена (Protobuf)
Вся коммуникация ведется в бинарном формате Protobuf (`Protobufmessages.proto`), что обеспечивает высокую скорость и строгую типизацию. Основные типы сообщений: `ModelMessage` (от модели) и `OrchestratorMessage` (от оркестратора).

## 🚀 Запуск и тестирование

### Предварительные требования
*   Java 17+
*   Maven
*   Docker и Docker Compose

### 1. Запуск Kafka
Для запуска инфраструктуры (Kafka в режиме KRaft + Kafka UI) выполните в корне проекта:
```bash
docker-compose up -d

Kafka будет доступна на `localhost:9092`. UI доступен на `http://localhost:8080`.*

### 2. Сборка и тесты
Проект содержит набор интеграционных тестов, включая стресс-тесты (кольцевая и полносвязная топология).
```bash
mvn clean test -Dgroups=integration-test
```

## 🔌 Интеграция с AnyLogic

Для подключения реальной модели AnyLogic к системе необходимо реализовать интерфейс `IEngine`.
Класс-адаптер должен делегировать вызовы движку AnyLogic, а события (`executeFirstStepEvent`, `executeStepEndEvent`) реализовывать через планирование `DynamicEvent`, чтобы гарантировать потокобезопасность.

**Пример инициализации в AnyLogic:**
```java
KafkaOrchestrant orchestrant = new KafkaOrchestrant("model-id", myEngine, myReceiver, true);
orchestrant.init();
```

## 📦 Структура проекта
*   `infrastructure/` — основные классы оркестрации, Protobuf-сгенерированные классы, интерфейсы.
*   `model/` — классы конфигурации (SimulationConfig, загрузчики JSON).
*   `utils/` — вспомогательные утилиты (работа со временем, логированием).
*   `src/test/` — интеграционные тесты и `TestEngine` (эмулятор движка для тестов).
